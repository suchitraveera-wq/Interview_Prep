## What this is

A Next.js web app for practicing AI PM interview questions: a random-draw
question page with category filtering and a timer, plus a resources page
(companies hiring + topic-based reading). No backend — all state is either
static JSON shipped with the build or browser `localStorage`.

## Stack

- Next.js 15 (App Router), TypeScript (`strict: true`)
- Tailwind CSS 3 — design tokens live in `tailwind.config.ts`, not
  hardcoded hex values in components
- Fonts via `next/font/google`: Space Grotesk (display), Inter (body),
  IBM Plex Mono (timer/category/company metadata)
- No external state library, no database, no auth

## Commands

```bash
npm install
npm run dev             # local dev server
npm run build            # production build — also the fastest way to catch type errors
npm run sync-questions    # refresh data/questions.json from the source Google Sheet
```

## Structure

```
app/
  page.tsx                 Practice page (/) — client component, owns filter/timer/question state
  resources/page.tsx        Resources page (/resources) — server component, static
  layout.tsx                 Root layout: fonts, nav, metadata
components/                  One component per concern: QuestionCard, Timer, CategoryFilter,
                              ProgressCounter, NavBar
lib/
  questions.ts               Question type, category extraction, random-pick logic (pure, no I/O)
  storage.ts                  localStorage read/write helpers, SSR-safe
data/
  questions.json               Question bank — regenerated by scripts/sync-questions.js, don't hand-edit casually
  resources.json                Companies + topic resources — currently placeholder content
scripts/
  sync-questions.js             Pulls the Google Sheet's published CSV export into data/questions.json
```

## Things to know before making changes

- **`data/questions.json` is generated, not hand-authored.** It's overwritten
  by `npm run sync-questions`. If you need to add/edit questions for
  testing, either edit the source Google Sheet and resync, or know that
  hand-edits here will be lost on the next sync.
- **Question IDs are position-based** (`q-002-brex`, generated from row
  order at sync time), not content-hashed. This means resyncing after the
  sheet's rows are reordered/deleted can shift IDs and orphan a user's
  `practicedIds` in localStorage. Known issue, not yet fixed — see
  `../Project Memory/technical-spec.md` §4 before "fixing" this casually,
  since the fix (hash-based IDs) has its own trade-offs to consider.
- **The Practice page is one client component**, not split further, because
  timer/filter/question state are tightly coupled (changing the filter or
  clicking Next both need to reset the timer). Don't split it into more
  components purely for tidiness without a real reason — see technical-spec.md §4.
- **`data/resources.json` content is placeholder.** The structure is meant
  to be stable; only the content inside needs replacing.
- **No test suite yet.** If you add one, `lib/questions.ts` (pure logic, no
  DOM/localStorage) is the highest-value starting point.
- **`npm audit` shows 3 high-severity findings**, all inside Next.js's own
  bundled `sharp`/`postcss` (used for image optimization, which this app
  doesn't use). Fixing requires jumping to Next 16 (breaking changes) — a
  deliberate decision, not an oversight. See technical-spec.md §5 before
  "fixing" this reflexively.
- **Fonts require network access at build time** (`next/font/google`
  downloads font files during `next build`). If a build fails specifically
  on font fetching in a sandboxed/offline environment, that's expected —
  it's not a code bug.
